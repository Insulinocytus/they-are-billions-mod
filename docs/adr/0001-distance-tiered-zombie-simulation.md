# ADR-0001：按玩家距离分层模拟僵尸

- 状态：已接受
- 日期：2026-09-05

## 背景

模组要求 1000 只普通 Zombie 聚集在同一战场并参与寻路、碰撞和挖掘时，服务端仍维持 20 TPS。对每只僵尸逐 Tick 执行相同精度的重新寻路和密集推挤无法提供固定成本上限。

## 决策

- 根据与最近玩家的距离降低仿真精度。
- 玩家附近保留原版局部导航和完整推挤。
- 中远距离降低重新寻路与推挤检查频率，允许同目标、同区域的僵尸共享粗路线，并限制每只僵尸处理的碰撞邻居数量。
- 客户端保留原版实体位置同步与插值；仅降低远处动画计算、阴影和非必要视觉效果。
- 保留原版 AABB，不通过缩小碰撞箱换取性能。
- 不使用随机 Leader。
- 首版不实现完整多高度流场；只有性能分析证明距离 LOD、错峰重新寻路和共享粗路线仍不足时才加入。
- 共享路线是按起点区域与目标区域缓存的不可变路点模板，不是由多只实体共享同一个可变 `Path`。每只实体持有独立游标；能直接到达附近前向路点时直接并入，否则才执行短程原版寻路。
- 共享路线最长缓存 5 秒；目标锚点移动超过 16 格、相关地形变化或同一路段连续三次无法通过时提前失效。单个实体因拥堵卡住不会使整条路线失效。
- 异步工作线程只处理主线程生成的不可变基础数据快照；实体、区块和方块的读取或修改均留在服务端主线程。
- 性能调节器使用最近 200 Tick 的窗口。P95 MSPT 超过 45 ms 时逐级降档，连续 200 Tick 低于 40 ms 时逐级恢复，40–45 ms 保持当前档位；最终可以暂停补充，但不修改管理员设置的目标值。
- 全服同时最多维护 64 个活跃挖掘点，并优先处理离玩家更近的障碍。
- 高负载时新挖掘点上限可以动态降低，最低为 8；已有挖掘进度保留。

## 后果

- 玩家附近保持高保真，中远距离行为允许近似。
- 距离、刷新频率和邻居上限必须通过目标硬件上的基准校准。
- 若以后实现流场，必须区分同一 X/Z 上的多个高度层；快照和失效版本可先与 16×16×16 Chunk Section 对齐。
