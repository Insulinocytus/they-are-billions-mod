# ADR-0002：接管普通 Zombie 的自然种群

- 状态：已接受
- 日期：2026-09-05

## 背景

模组需要把普通 `Zombie` 的夜间数量控制在固定服务器预算内，并在白天主动降低地表与洞穴密度。若同时保留原版自然生成，模组无法稳定控制数量和性能；若禁止所有实体创建，则会破坏命令、刷怪笼、地图与其他模组。

## 决策

- 禁止普通 `Zombie` 的原版自然生成、区块生成和增援，由模组统一调度这些来源。
- 模组生成尸潮时绕过原版 Monster 数量上限，但尸潮成员生成后仍计入该上限；其他敌对生物会自然停止补充，而不是被主动清除。
- 保留命令、刷怪蛋、刷怪笼、转化及其他模组显式创建的普通 `Zombie`。
- 所有已加载并 Tick 的普通 `Zombie` 都占用服务器总量预算，不区分来源。
- 首版不接管 `Husk`、`Drowned` 或 `Zombie Villager`。
- 白天复用原版阳光燃烧条件筛选地表目标，并按 Chunk Section 密度筛选地下目标。
- 清理通过服务端主线程限额队列直接移除，每 Tick 最多 10 只，不产生死亡事件、经验或掉落；命名和持久化实体豁免，但仍占用局部密度名额。
- 模组生成的尸潮成员正常死亡时也不产生物品或经验；显式创建的普通 `Zombie` 保留原版死亡掉落。

## 后果

- 远处生成环忽略亮度，仅铺设火把不能关闭核心玩法；其余位置合法性与标准生成事件仍然生效。
- 刷怪笼、命令或其他模组创建的僵尸过多时，会占满预算并阻止尸潮补充，但不会被夜间强制删除。
- 依赖原版自然 Zombie 生成事件的其他模组可能不再收到这些事件，需要按实际兼容问题处理。
