# ADR-0004：强制 Tick 160 格内的尸潮区块

- 状态：已接受
- 日期：2026-09-06

## 背景

尸潮需要在原版 128 格立即清理范围之外生成并持续向玩家移动。仅提高实体的清理距离不能使模拟距离之外的实体继续活动，因为未参与实体 Tick 的区块不会更新其中的 Zombie。

## 决策

- 尸潮在对应玩家群组 128–144 格处生成并忽略亮度限制；144–160 格作为追猎缓冲。
- 距所有有效玩家超过 160 格的未命名、非持久化尸潮成员立即移除。
- 160 格内，所有包含模组尸潮成员的区块都申请实体 Tick 票据，不设票据数量硬上限。
- 只有模组生成的尸潮成员可以申请票据；刷怪笼、命令和其他模组创建的 Zombie 不可以。
- 票据按占用区块引用计数：先申请目标区块再允许成员进入，最后一只成员离开后释放。票据采用短超时并周期续期，避免异常留下永久强制加载。
- 尸潮成员身份及占用区块索引持久化；有效玩家上线后重新申请票据、核验实体、关联最近玩家群组并恢复导航。
- 没有有效玩家在线时不生成尸潮，也不续期票据。未命名、非持久化成员逐步清理；命名或持久化成员等待区块以后自然加载。

## 后果

- 单玩家理论范围约为 10 区块半径、317 个中心区块，另有票据传播所需的支撑区块。
- 一个区块内的所有实体都会参与 Tick，而非仅尸潮成员。
- 1000 只 Zombie、20 TPS 是必须通过基准追求的目标，而不是在任意尸潮分布下的无条件保证。
